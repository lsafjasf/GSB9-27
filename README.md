# GSB9-27 报表缓存改造

按数据版本失效的报表缓存库（Python 3，仅标准库），替代「每次全量重算」与「简单缓存 + 固定过期」两种旧方案。

## 设计

- `DataRegistry`：底层数据的版本注册表，每次写入递增版本并记录变更时间。
- `ReportCache`：每个缓存条目保存构建时的依赖版本快照；读取时逐依赖比对版本，
  只失效受影响的报表（不全量清空），下次读取即在可接受时间内刷新。
- 版本快照在重算开始前采集；版本校验与条目写回在同一临界区内完成。
  重算窗口内若依赖被写入，按旧数据算出的结果会被丢弃并重试，绝不会盖上
  新版本号写回（否则该陈旧条目将长期骗过版本校验）。
- 同一报表的并发未命中通过 single-flight 合并为一次重算，避免失效风暴。
- 重算失败保留并返回旧值；同一数据版本在冷却期内不重复重试，防止失败风暴。
- 时间通过 `time_fn` 注入，测试使用假时钟，结果可复现。
- `TTLReportCache`：固定过期时间的对照实现，用于基准对比。

## 运行

```bash
python3 -m unittest discover -s tests -v   # 并发与失效测试（10 个用例）
python3 benchmark.py                        # 命中率 / 陈旧度 / 重算次数对比
```

## 基准结论（5000 次读取、4 张报表、3 份数据、TTL=10s）

| 指标 | 按版本失效 | 固定 TTL |
| --- | --- | --- |
| 命中率 | 92.0% | 90.4% |
| 重算次数 | 402 | 479 |
| 读到陈旧数据的次数 | 0 | 1427 |
| 平均陈旧时长 | 0s | 3.09s |

固定 TTL 在「数据没变却到期重算」上浪费算力，又在「数据变了还没到期」时持续返回旧数据；
按版本失效只在数据真正变化且报表被读取时重算，读到的数据始终与底层一致。
