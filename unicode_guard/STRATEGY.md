# 策略说明：归一化、同形与不可见字符处理

## 1. 三个环节各用哪种形式

| 环节 | 函数 | 形式 | 理由 |
|------|------|------|------|
| 比较 | `canonical_key()` | 剥不可见 → NFKC → casefold → NFKC → 同形骨架 → NFC | 把所有视觉/大小写/兼容等价体折叠到同一键，黑名单与占用名都先转成键再比对，绕过无效 |
| 存储 | `storage_form()` | 剥不可见后的 NFC | 去掉不可见字符（它们对合法用户只有害处），但保留用户选择的可见字符与大小写；NFC 保证同一文本在库中字节唯一 |
| 展示 | `display_form()` | 原始输入的 NFC | 展示必须尊重用户原貌（大小写、字符选择），只做无害的规范化，绝不折叠、绝不静默替换 |

要点：**等价性判断只发生在比较环节**。存储与展示形式不参与安全判定，
因此即使两个用户视觉相似，只要比较键不同就各自独立；键相同则在注册期被拦截。

## 2. 归一化 + 大小写折叠的组合

顺序固定为：`strip_invisible → NFKC → casefold → NFKC → skeleton → NFC`。

- 先 NFKC 再 casefold：兼容字符（全角、上标等）先展开，折叠才能命中。
- casefold 后再 NFKC：折叠可能产生新的兼容序列（如 `ﬁ` → `fi`），需二次归一。
- `canonical_key` 幂等（有测试保证），因此黑名单条目与待检串用同一函数即可。

## 3. 风险类别与可配置策略

每类风险独立配置 `Policy.REJECT / WARN / REPLACE`（见 `Config`）：

- **不可见字符**（`invisible`）：Cf/Cc 类、变体选择符、标签字符、软连字符。
  合法用户名几乎不需要它们，生产建议 `REJECT`；`REPLACE` 时直接剥离。
- **同形字符**（`confusable`）：内置西里尔/希腊等伪装成拉丁字母的映射表，
  检出后映射到骨架字符。建议 `WARN`（记录审计）或 `REJECT`（高安全场景）。
- **混用文字系统**（`mixed_script`）：同一标识符混用拉丁+西里尔/希腊等。
  纯单一文字系统（如纯西里尔用户名）不告警。
- **非规范组合顺序**（`non_nfc`）：组合符顺序被调换。NFC 即可消除，
  固定按 `REPLACE` 处理，永不拒绝。

无论策略如何配置，**比较键始终包含全部折叠**——策略只决定"放行/拒绝/清洗"，
不影响等价性判定，保证安全语义不随配置漂移。

## 4. 等价性自洽

`a ≡ b ⟺ canonical_key(a) == canonical_key(b)`。测试断言：

- 自反、对称、传递（`TestEquivalenceRelation`）；
- 两两等价导出的分组 == 按键分组 == 期望等价类划分；
- 键幂等：`key(key(k) == k`。

## 5. 已知边界

- 同形表是精选子集（标准西里尔/希腊高频伪装字符），非完整 UTS#39 全表；
  标准库无 confusables.txt，需要全覆盖时应引入该数据文件生成映射。
- 数字/字母形似（`0/O`、`1/l`）未默认折叠，避免误伤合法用户名；
  需要时可在 `CONFUSABLES` 中追加。
