# 度量规则表

## 1. 函数级复杂度（扩展圈复杂度）

基线为 1（一条直线路径），每个"判定點"按下表加分。复杂度 ≈ 函数内独立执行路径数的下界，
对应"彻底测试该函数所需的最少用例数"，与理解/修改难度正相关。

| 构造 | 计分 | 规则说明 |
|---|---|---|
| 函数基线 | +1 | 无分支的直线代码恒为 1（超长直线函数也是 1） |
| `if` / `elif` | 每个 +1 | 每个条件产生一条新路径；嵌套 if 逐层累加 |
| `else` | +0 | 不引入新判定 |
| `for` / `async for` | 每个 +1 | 循环体执行 0 次或多次 |
| `while` | 每个 +1 | 同上 |
| 循环的 `else` | +0 | 依附于循环，不单独计 |
| 三元表达式 `a if c else b` | 每个 +1 | 等价于一个 if |
| 逻辑短路 `and` / `or` | n 个操作数 +(n-1) | 短路求值等价于嵌套判定；`a and b and c` 是 3 操作数，+2 |
| `try` 的 `except` 子句 | 每个 +1 | 每条异常捕获路径是一个判定 |
| `try` / `else` / `finally` | +0 | 本身不产生分支 |
| `return`（提前返回） | 第 2 个起每个 +1 | 多个出口 = 隐式分支；单个 return 不计 |
| `assert` | 每个 +1 | 隐式条件分支（失败即异常路径） |
| `match` 的每个 `case` | 每个 +1 | 结构化模式分派，每个 case 一条路径 |
| 推导式的 `for` 子句 | 每层 +1 | 等价于循环 |
| 推导式的 `if` 子句 | 每个 +1 | 等价于过滤条件 |
| `with` / `async with` | +0 | 协议调用，非判定 |
| 嵌套 `def` / `lambda` / `class` | 不计入外层 | 作为独立函数单独度量（lambda 不单独出报告） |
| 装饰器 | +0 | 调用语义，非判定 |

### 典型构造的计分示例

| 代码 | 得分拆解 | 复杂度 |
|---|---|---|
| `def f(): pass` | 基线 | 1 |
| 41 行纯赋值（`f03_long_straight`） | 基线 | 1 |
| `if a and b or c:` | if(1) + and(1) + or(1) | 4 |
| 3 层嵌套 if + 2 个 return | if×3 + 提前返回×1 | 5 |
| try + 3 个 except | except×3 | 4 |
| 4 个 return 的卫语句函数 | if×3 + 提前返回×3 | 7 |

## 2. 模块间耦合度

对分析目录内的每个模块统计（仅计入目录内部的依赖，标准库/第三方忽略）：

| 指标 | 定义 | 含义 |
|---|---|---|
| Ce（被引用数 / efferent） | 本模块 import 的内部模块数 | 越高越"脆弱"：依赖的任何模块变动都可能波及它 |
| Ca（被依赖数 / afferent） | import 本模块的内部模块数 | 越高越"责任大"：改动它的影响面越广 |
| 不稳定性 I = Ce/(Ca+Ce) | 0..1 | 0 = 最稳定（只被依赖），1 = 最不稳定（只依赖别人）；孤立模块记 0 |

导入解析规则：

- `import a.b.c`：解析到分析树内**最具体**的已知模块（`a.b.c` 不在则退到 `a.b`、`a`）。
- `from pkg import sub`：若 `pkg.sub` 是树内模块则计 `pkg.sub`；否则计 `pkg`。
- 相对导入（`from . import x`、`from ..pkg import y`）先按包层级换算为绝对名再解析。
- 自引用、重复导入只计一次；语法错误的模块按孤立模块处理（Ca=Ce=0）。

## 3. 为什么不用行数

行数把"长而直"的代码误判为复杂。样本中的 `f03_long_straight`（41 行纯赋值）
人工难度评 2/10，行数会把它排到前列，而本度量给出复杂度 1——与人工判断一致
（见 `samples/annotations.json` 与 `scripts/compare_annotations.py` 的对拍结果）。
