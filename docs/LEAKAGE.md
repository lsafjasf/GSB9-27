# 泄露面评估（Leakage Analysis）

方案：盲索引标签（HMAC-SHA256，128 bit 截断，带密钥版本）+ AES-256-GCM 可逆密文（AAD 绑定 recordId/field/tag/版本）。
本文件说明该方案**会向持有数据库快照的攻击者泄露什么、不泄露什么**，并对不均匀分布给出量化。

## 1. 不泄露的内容

| 项目 | 保护机制 |
|---|---|
| 明文本身 | AES-256-GCM，语义安全（随机 nonce），密文不可区分 |
| 标签 → 明文反推 | HMAC 是带密钥 PRF；**无密钥无法离线字典爆破标签**（这是与"直接落 SHA-256"的本质区别：朴素哈希对低熵字段可被彩虹表/字典反查，HMAC 不能） |
| 跨字段等值关系 | 标签计算混入字段名，`email=x` 与 `name=x` 标签不同 |
| 跨密钥版本的标签关联 | 轮换后标签用新密钥重建，新旧标签不可关联（但见 §3 第 4 条） |
| 密文跨记录/跨字段搬移 | GCM 的 AAD 绑定 `(版本, recordId, field, tag)`，复制即认证失败 |

## 2. 必然泄露的内容（确定性等值索引的固有泄露）

1. **等值泄露（equality leakage）**：同一字段内，相同明文 ⇔ 相同标签。攻击者可看到每个取值出现了多少次、哪些行相同。
2. **频率泄露（frequency leakage）**：每个标签组的行数即该取值的频数，与明文分布完全同构。
3. **长度泄露**：GCM 密文长度 = 明文长度 + 28 字节（nonce+tag 另计），可据此推断明文长度。
4. **空值泄露**：`NULL` 不加密，攻击者知道哪些记录该字段为空。
5. **查询时的访问模式泄露**：等值查询命中哪些行，对观察查询结果的攻击者可见。
6. **时间维度关联**：两次快照对比可知哪些行被修改（标签/密文变化）。

## 3. 不均匀分布下的量化风险

设字段取值分布为 `{p₁, p₂, …, p_k}`（攻击者从公开统计可得的先验），共 N 行。

**频率匹配攻击**：攻击者把观察到的标签组大小排序，与先验分布排序对齐，即可建立 标签→明文 的映射。

- 攻击者**不用任何密文**直接猜一条记录取值的成功率基线：`P₀ = max_i p_i`。
- 频率匹配后，只要各组大小可区分（`N·p_i` 互不相同，N 稍大即成立），攻击者对**几乎每一条记录**都能确定其取值：成功率 → 1。
- 因此**攻击者优势 ≈ 1 − max_i p_i**。分布越不均匀（max p_i 越大），基线越高，但频率攻击使剩余不确定性也归零。

**具体算例**（N = 100,000 的用户表）：

| 字段 | 分布 | 无密文猜测基线 | 频率攻击后可确定取值的记录 |
|---|---|---|---|
| 性别 | 99% / 1% | 99,000 行 | ≈ 100,000 行（两组大小 99000/1000 一眼可分） |
| 血型 | 40/30/20/10% | 40,000 行 | ≈ 100,000 行 |
| 手机号 | 近似唯一（k≈N） | ≈ 0 行 | 频率攻击无效；但见下条 |

**结论**：
- **低基数、分布不均匀的字段（性别、状态、省份）不适合做盲索引**——等值标签等于明文。这类字段应只加密、不建索引，或接受泄露。
- **高基数字段（手机号、邮箱、证件号）频率攻击基本无效**：每组只有 1–2 行，无法靠频率对齐。主要残余风险是攻击者持有候选明文集时的**在线验证**（见 §4）。
- 唯一值（组大小 = 1）本身即泄露"该记录取值唯一"这一事实。

## 4. 残余风险：在线字典验证

若攻击者已控制应用层或可诱导查询，可对候选明文 `m` 计算查询标签（通过正常查询接口）验证"某行是否等于 m"。标签是确定性的，**无法防止在线字典攻击**，只能靠：
- 查询限流 / 审计（应用层职责）；
- 仅持有数据库快照、不持有密钥的攻击者**无法**做此验证（HMAC 无密钥不可算），这是本方案相对朴素哈希的核心收益。

## 5. 与「可搜索加密」（SSE）方案的取舍

| 维度 | 本方案（盲索引 + AEAD） | 典型 SSE（如 OXT/动态 SSE） | OPE/ORE | FHE/ORAM |
|---|---|---|---|---|
| 等值查询 | ✅ 标签精确匹配，O(索引) | ✅ | ✅（还保序） | 理论可行 |
| 范围/排序查询 | ❌ | 部分构造支持 | ✅（但泄露顺序，已被证明弱） | 理论可行 |
| 等值/频率泄露 | 有（见 §2） | 有（访问模式泄露，量级相当） | 额外泄露**顺序**，更弱 | 可消除 |
| 离线字典攻击 | 免疫（HMAC 带密钥） | 免疫 | 免疫 | 免疫 |
| 实现复杂度 | 标准库 200 行 | 需专门库+索引结构 | 需专门库 | 极高 |
| 查询性能 | 与普通索引同阶 | 接近 | 接近 | 差几个数量级 |
| 密钥轮换 | 重建标签+重加密（本库已支持断点续跑） | 类似 | 类似 | — |

**取舍结论**：本方案用「等值+频率泄露」换取「零依赖、索引级性能、可审计的小代码量」。对高基数字段（邮箱/证件号/手机号）这是合理平衡；对低基数或需范围查询、需隐藏访问模式的场景，应评估 SSE 或接受不建索引。

## 6. 轮换相关的泄露说明

- 轮换重建标签后，**仅凭新旧标签**无法关联（不同 HMAC 密钥）。
- 但攻击者若持有轮换前后的两份快照，可通过**行身份**（recordId 不变）把旧标签与新标签对应起来——轮换不能抹去历史快照已泄露的等值关系。轮换的意义在于：旧密钥泄露后，其对应的标签计算能力失效，新写入的数据获得前向保护。
